## Findings

### F1 — contract gap: nonce consumption is nobody's job (**highest value**)

`canon.py::promote` looks up the gate by `decision_nonce` and then appends the
decision and the revision. **It never checks whether that nonce was already
used, and nothing else in the nine modules does either.** The one-time human
decision property — `THREAT_NOTES_FOR_BUILDERS.md` abuse case 3 — is silently
delegated to the ledger, and `LEDGER_SPEC_FOR_GROK.md` §2–§3 never asked for
it.

Measured, not argued. A ledger satisfying every hard requirement in the spec
and nothing more was built and run against Codex's own suite:

```
FAILED tests/test_canon_hostile.py::test_human_promotion_consumes_nonce_once
E   Failed: DID NOT RAISE AuthorizationError
1 failed, 57 passed
```

This is a design flaw inherited from the contract, not an implementation bug —
precisely the class the brief said the builder split cannot catch. Recorded as
`LEDGER_SPEC_FOR_GROK.md` §8, which promotes it to hard requirement 8 so the
Grok seat is not set up to ship a known-broken build.

### F2 — `api.propose_signal` denies without an audit trail

Every other denial path appends `permission.denied` before raising. This one
raises bare, so a rejected `system` actor leaves no trace. Verified: event
count unchanged, zero `permission.denied` rows. Pinned by a `strict=True`
xfail so fixing it reports XPASS rather than passing silently. Low severity —
models are permitted to propose signals, so this does not weaken the canon
wall — but it breaks the "every rejection leaves a mark" property the threat
model implies. **Open, not fixed** (it is Codex's module).

### F3 — `workflow.gates.promote_canon` is validated, never consulted

The compiler pins the gate to the single literal `human_only`, and no
promotion path ever receives a `WorkflowIR`. The canon wall is real, but it is
enforced by the actor-kind check in `canon.py`, not by the declared gate.
Demonstrated by promoting canon in a run where no workflow is compiled at all.
Declared-versus-enforced: harmless today, misleading to a future reader who
assumes the gate is doing work.

### F4 — `policy.changed` is write-only

Nothing reads a recorded policy back. Recording `canon.mode = model_allowed`
changes nothing — the safe direction, but the surface should not be read as
configurable authority.

### F5 — the public boundary is a declaration, not a mechanism

`THREAT_MODEL.md` names `forge_core.Forge` as the supported boundary and
`__all__` excludes the internals, but Python still imports `EventLedger`,
`ArtifactStore`, and `CapabilityEngine` on request. `THREAT_NOTES` listed
"capability bypass via internal helpers exposed publicly" as an **in-scope
defense**; `THREAT_MODEL.md` quietly converted it into a scope declaration.
Whether a second wall catches such a caller depends entirely on the installed
ledger — measured by `test_ledger_beyond_contract.py`, which skips when absent.

### F6 — capability grants cannot be revoked

No event type withdraws a grant; `capability.has` stops at the first match. A
disclosure is permanent for the life of the domain. Not claimed anywhere, so
not a defect — recorded so it is not mistaken for a feature.

### F7 — tail truncation is undetectable (limitation, not a bug)

Deleting the newest events leaves a shorter chain in which every link and hash
is intact. No in-file hash chain can detect this without an external tip
anchor. Middle-row deletion, row corruption, and events spliced from a
divergent chain **are** all detected. `THREAT_MODEL.md` covered "rewriting the
entire history consistently" but not this much cheaper attack. Added to
`THREAT_MODEL.md` under a clearly attributed debug-seat heading, and pinned by
a test so a future anchor shows up as a behavior change.

## Attacking my own tests — mutation results

A test that passes against code the same seat just wrote proves very little.
Twelve deliberate defects were injected one at a time; each had to turn a
named test red.

**First run: 3 of 12 survived.** The tests that were supposed to catch them
were passing for the wrong reason:

- prev_hash link checking was covered only incidentally by hash recomputation
- sequence-gap detection was masked by the link check
- one guard was reachable only on a path the test never took

Two new tests were written to isolate those defenses — a self-consistent event
spliced from a divergent chain, and a forged head with the wrong `seq` — and
one harness target was corrected. **Second run: 12 of 12 killed.**

The three survivors are reported because they are the most useful thing in
this section: without mutation testing, that suite would have looked complete
and been quietly weaker than it read.

## Test harness handed forward

The tests are this seat's actual deliverable, and they were restructured so
they judge **any** ledger written to the spec rather than mirroring the
quarantined one:

- `test_hash_chain.py` — contract-level only; matches on exception **type**,
  not message text; uses only the 4-argument `append` signature the spec pins
- `test_replay.py` — restart, subprocess replay, events-only truth, denial
  durability, nonce persistence
- `test_ledger_beyond_contract.py` — properties the spec does **not** require
  (actor-kind catalog, lifecycle ordering, storage-level triggers). Each
  probes the installed ledger and **skips** with a reason when absent, so a
  spec-minimal implementation reports skips, not failures
- `test_debug_seat_findings.py` — F2–F6 against Codex's modules

Fairness was verified by running the whole harness against a deliberately
spec-minimal ledger: **2 failed, 83 passed, 4 skipped, 1 xfailed** — and both
failures point at F1, the one real contract gap. An earlier version of the
harness failed 6, four of them for unfair reasons (conflating the nonce gap
with replay, and asserting a beyond-spec property in a contract test). Those
were fixed.
