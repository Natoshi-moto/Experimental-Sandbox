## Raw origin (verbatim tension)

- **Claude (Fable, 2026-07-25):** the project's recursion risks being *"turtles all the way down"* — self-referential trust-verification with no external object.
- **Operator:** *"You say turtle, I say isomorphism."* — the recursion is structural self-similarity, a **feature**, not empty regress.

This experiment converts that disagreement into a falsifiable claim and asks every reachable model to try to break it.

## The two rival readings

**H1 — ISOMORPHISM (feature).** The project instantiates one structural invariant — call it the **verifiable-trust invariant, P** — and ports it, structure-preserving, across genuinely distinct domains (governance/audit, software/product, economy/commons, creative/artistic). The repetition is *generative*: the same form solves the same problem at each scale, which is *how* trust scales without a central authority. Recursion here is a good abstraction reused across a codebase — economy, not emptiness.

**H0 — TURTLES (null).** The recursion is degenerate self-reference. The "layers" are one meta-layer relabeled; the system verifies trust about trust with **no external object** — no inhabited domain (real artist, real user, real economy) where the invariant meets reality instead of another copy of itself. Any "isomorphism" is trivial (everything maps to itself) and therefore unfalsifiable.

## The invariant under test (P) — stated so its presence/absence is checkable

1. Every claim carries its **evidence tier** (verified / attested / testimony / unverifiable).
2. A **declared** property is not trusted until **mechanically enforced**; unenforced properties are marked, not assumed.
3. **No privileged actor** (no admin / founder / AI bypass); authority is explicit and recorded.
4. **Provenance is append-only, inspectable, and self-binding.**

Open sub-question: is P a single invariant, or several patterns bundled under one name?

## Tests (each independently checkable; run any subset)

### T1 — Atomicity
Is P one invariant or a bundle? If it fragments under inspection, the "single isomorphism" claim weakens toward H0.

### T2 — The mapping (isomorphism proper)
For H1 to be more than analogy, specify objects + morphisms per layer and exhibit a **structure-preserving map**. Candidate mapping — **attack it**:

| governance / audit | product / software | economy / commons | creative / artistic |
|---|---|---|---|
| `status_authority: NONE` | capability ≠ JS access | STRICT NO SALE (no transfer interface) | recognition ≠ purchase |
| merge-authorization file | permission gate / receipt | signed authorship anchor | attribution provenance |
| seal/unseal non-contamination | sandboxed origin boundary | key custody | **??? (does this column exist yet?)** |

**Falsifier:** if the mappings are post-hoc, non-bijective, or the fourth (artistic) column cannot be filled with real referents, H1 is **not yet demonstrated**.

### T3 — External-object test (the decisive one)
H1 predicts P holds and stays **non-vacuous** when instantiated in a genuinely **external** domain (a real artist + real artwork in the commons; a real cold-start user of the assistant). H0 predicts P becomes vacuous or fails on contact — collapsing into metric-tyranny, first-to-sign land-grab, or social-capture (the documented downstream risks).

**Smallest test:** instantiate P once with a real creative act, observe whether it preserves value non-trivially or degenerates.
**Falsifier for H1:** P degenerates on first external contact. **Falsifier for H0:** P holds and predicts something non-obvious about the external domain.

### T4 — Declared→Enforced conversion (measurable from repo history)
The project repeatedly **declares** P and lags **enforcing** it (STRICT NO SALE without a forbidden-surface scanner; capability ≠ JS-access with the live pop-out hole T-01b; commons impact declared, not studied) — yet sometimes closes the gap (PR #110 promotion gate: critique → fix → re-authorize → merge, same morning).

- **H1 reading:** enforcement lag is incidental; the declared→enforced conversion rate is positive and rising as the system matures.
- **H0 reading:** *declaration-outrunning-enforcement is itself the tell* — the system specifies itself endlessly but cannot cross into enforcement because there is no external ground to enforce against.

**Test:** measure the declared→enforced conversion rate over git history (declared MUSTs vs. mechanically-enforced ones; trend over time). Rising ⇒ H1; declarations accumulating faster than enforcement ⇒ H0.

## Discrimination rule
- T3 degenerates **and** T4 trend negative **and** T2 artistic column empty ⇒ **TURTLES**.
- T2 map bijective + non-trivial **and** T3 holds on external contact **and** T4 trend positive ⇒ **ISOMORPHISM**.
- Mixed outcomes are expected and legitimate — report the pattern; do not force a verdict.

## Author's prior, stated openly (the author is not neutral)

## Falsifier for this experiment as a whole
If no model can specify a non-trivial structure-preserving mapping (T2) **and** no external-object instantiation (T3) is ever run, the thesis is **UNFALSIFIABLE-AS-STATED** — which is itself evidence for H0: a claim that cannot be made to touch an external object.
